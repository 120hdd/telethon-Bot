00 / معرفی

این پروژه دقیقاً چه می‌کند؟

SajadBot پیام‌ها را از حساب شخصی شما به گروه‌هایی می‌فرستد که از قبل عضو آن‌ها هستید و خودتان صریحاً مجازشان کرده‌اید. هدف، ارسال مطمئن و قابل پیگیری است؛ نه ارسال انبوه یا دورزدن محدودیت‌های تلگرام.

صف پایدار

همه‌ی کارها در SQLite ثبت می‌شوند؛ بنابراین با توقف برنامه، پیام‌های ارسال‌نشده از بین نمی‌روند.

ارسال و زمان‌بندی

متن و فایل را همان لحظه یا برای زمان آینده صف کنید. زمان‌ها در پایگاه داده به‌صورت UTC نگه‌داری می‌شوند.

مقصدهای سفید

گروه‌های تازه کشف‌شده غیرفعال‌اند و فقط پس از دستور allow مقصد ارسال می‌شوند.

کنترل از Saved Messages

صف، گروه‌ها و ارسال‌ها را از پیام‌های ذخیره‌شده‌ی همان حساب مدیریت کنید؛ ورودی‌های دیگر نادیده گرفته می‌شوند.

تلاش مجدد حساب‌شده

FloodWait و Slow Mode رعایت می‌شوند؛ خطاهای شبکه با وقفه‌ی افزایشی و سقف تلاش مدیریت می‌شوند.

قابل مشاهده و حسابرسی

وضعیت صف، سلامت اتصال و رویدادهای مهم ثبت می‌شوند؛ بدنه‌ی پیام‌ها به‌طور پیش‌فرض وارد لاگ نمی‌شود.

01 / پیش‌نیاز

قبل از شروع

سه مورد لازم است: پایتون جدید، مشخصات API تلگرام و حسابی که از قبل عضو گروه مقصد باشد. اجرا روی ویندوز و Ubuntu Server پشتیبانی می‌شود.

روی سیستم

  • Python نسخه‌ی ۳.۱۲ یا جدیدتر
  • PowerShell روی ویندوز یا Ubuntu 24.04 LTS برای سرور
  • دسترسی نوشتن در پوشه‌ی پروژه
  • اینترنت پایدار برای اتصال به تلگرام

از تلگرام

  • یک حساب شخصی فعال
  • عضویت قبلی در گروه‌های مقصد
  • api_id و api_hash از my.telegram.org
  • دسترسی به کد ورود و رمز دومرحله‌ای، در صورت فعال بودن
مرز استفاده

این ابزار برای چرخاندن حساب‌ها، تعویض پروکسی جهت دورزدن محدودیت یا ارسال پیش از پایان زمان اعلام‌شده‌ی تلگرام طراحی نشده است.

03 / سرور Ubuntu

اجرای دائمی با systemd

اسکریپت نصب، برنامه را در مسیر استاندارد سرور قرار می‌دهد، یک کاربر محدود سیستمی می‌سازد و سرویس را برای اجرای پایدار آماده می‌کند. Ubuntu 24.04 LTS پیشنهاد می‌شود؛ چون Python 3.12 را به‌صورت رسمی ارائه می‌کند.

۱

انتقال پروژه و نصب

پوشه‌ی پروژه را با Git، SCP یا SFTP روی سرور قرار دهید، وارد ریشه‌ی آن شوید و نصب‌کننده را اجرا کنید. نصب‌کننده بسته‌های سیستم، محیط مجازی، کاربر sajadbot و فایل سرویس را می‌سازد؛ اما در نصب اول سرویس را پیش از ورود تلگرام روشن نمی‌کند.

Ubuntu / Bash
cd /path/to/SajadBot
sudo install -o root -g root -m 0755 scripts/ubuntu/tgs.py /usr/local/bin/tgs
sudo tgs install .

فعال‌سازی و مشاهده‌ی سرویس

پس از ورود موفق، سرویس را فعال کنید تا همین حالا و پس از هر reboot اجرا شود. برنامه پورت ورودی باز نمی‌کند و فقط اتصال خروجی به تلگرام نیاز دارد.

systemd
sudo tgs enable --now
sudo tgs status
sudo tgs logs --follow

مسیرهای نسخه‌ی سرور

  • برنامه: /opt/sajadbot
  • تنظیمات: /etc/sajadbot/sajadbot.env
  • دیتابیس و session: /var/lib/sajadbot
  • لاگ فایل: /var/log/sajadbot/app.log

مدیریت و به‌روزرسانی

Ubuntu / Bash
# راهنمای اصلی و راهنمای هر ساب‌کامند
tgs -h
tgs update -h
tgs auth login -h

# بررسی امن و مدیریت سرویس
sudo tgs check
sudo tgs restart
sudo tgs logs --follow

# آپدیت از checkout جدید؛ تنظیمات و داده‌ها حفظ می‌شوند
sudo tgs update /path/to/newer/SajadBot
از اجرای هم‌زمان CLI و سرویس خودداری کنید

فرمان‌هایی مثل groups refresh که session تلگرام را باز می‌کنند باید وقتی سرویس متوقف است اجرا شوند: sudo systemctl stop sajadbot. فرمان‌های عادی صف و وضعیت به session دست نمی‌زنند.

05 / گروه‌ها

کشف، نام‌گذاری و مجازکردن مقصد

عضویت در گروه به‌تنهایی کافی نیست؛ هر مقصد باید پس از refresh صریحاً در فهرست مجاز قرار بگیرد.

allowمجازکردن مقصد
aliasنام کوتاه اختیاری

مدیریت گروه‌ها
python run.py groups refresh
python run.py groups list
python run.py groups allow -1001234567890
python run.py groups alias -1001234567890 work
python run.py groups allowed
لغو دسترسی مقصد

دستور python run.py groups deny work مقصد را غیرفعال می‌کند و همه‌ی کارهای صف‌شده و ارسال‌نشده‌ی آن را بلافاصله لغو می‌کند.

06 / ارسال

ارسال متن، فایل و پیام زمان‌بندی‌شده

فرمان‌ها ابتدا کار را در SQLite ثبت می‌کنند. اگر worker فعال باشد آن را برمی‌دارد؛ در غیر این صورت تا اجرای بعدی start در صف می‌ماند.

ارسال متن

PowerShell
python run.py send --group work --text "Deployment completed."

ارسال فایل با توضیح

PowerShell
python run.py send --group work --file ".\report.pdf" --text "Weekly report"

زمان‌بندی محلی

PowerShell
python run.py send --group work --text "Reminder" --at "2026-09-20 14:30"

گزینه‌های تکمیلی

PowerShell
python run.py send --group work --text "<b>Done</b>" --parse-mode html --disable-link-preview
جلوگیری از ارسال تکراری

فرمان معادلِ تکراری به‌طور خودکار سرکوب می‌شود. فقط وقتی تکرار عمدی است گزینه‌ی --force را اضافه کنید.

فایل زمان‌بندی‌شده مستقل می‌ماند

رسانه‌ی صف‌شده به مسیر data/uploads/<job-uuid>/ کپی می‌شود؛ پس جابه‌جایی فایل اصلی باعث خرابی ارسال آینده نمی‌شود.

چه چیزی پذیرفته می‌شود؟

چه پاسخی می‌گیرید؟

پس از صف‌شدن کار پاسخ اولیه دریافت می‌کنید و بعد از تحویل یا شکست نیز وضعیت نهایی اعلام می‌شود.

09 / پایداری

رفتار برنامه هنگام خطا

برنامه به‌جای تلاش تهاجمی، وضعیت را ثبت می‌کند و محدودیت‌های اعلام‌شده از سوی تلگرام را رعایت می‌کند.

محدودیت ارسال

FloodWait و Slow Mode با زمان تلاش بعدی ذخیره می‌شوند. FloodWait بزرگ‌تر از آستانه‌ی تنظیم‌شده، کل خروجی را تا موعد مقرر متوقف می‌کند.

اختلال شبکه

خطاهای موقت با وقفه‌ی افزایشی محدود و کمی jitter دوباره امتحان می‌شوند تا فشار ناگهانی ایجاد نشود.

احراز هویت

خطای مجوز حساب، worker را متوقف می‌کند و به ورود دوباره‌ی اپراتور نیاز دارد؛ صف بدون کنترل جلو نمی‌رود.

محتوا یا مقصد نامعتبر

خطای دسترسی گروه، مقصد یا محتوای نامعتبر بدون تلاش کورکورانه شکست می‌خورد.

10 / امنیت

session همان اعتبار حساب است

فایل session، رمز دومرحله‌ای، API hash و کدهای ورود را مثل اطلاعات محرمانه نگه دارید.

انجام دهید

  • پوشه‌ی data/sessions را خصوصی نگه دارید.
  • فقط نسخه‌ی رمزنگاری‌شده‌ی داده‌های حساس را پشتیبان بگیرید.
  • LOG_MESSAGE_BODIES=false را حفظ کنید.
  • مجوز گروه‌های غیرضروری را با deny بردارید.

انجام ندهید

  • فایل .env یا session را commit نکنید.
  • session را از طریق وب یا static hosting منتشر نکنید.
  • کد ورود، رمز یا API hash را در خط فرمان و لاگ ننویسید.
  • برای دورزدن FloodWait برنامه را پیاپی restart نکنید.

12 / عیب‌یابی

وقتی چیزی طبق انتظار نیست

ابتدا status و queue list را ببینید؛ سپس مورد متناظر را بررسی کنید.

FloodWait یا SlowMode دیده می‌شود

برنامه تا زمان اعلام‌شده‌ی تلگرام صبر می‌کند. وضعیت صف را بررسی کنید و برای دورزدن انتظار، سرویس را مرتب restart نکنید.

session مجاز نیست یا اتصال متوقف شده

روی ویندوز python -m app auth login را تعاملی اجرا کنید. روی Ubuntu ابتدا سرویس را متوقف و سپس sudo -u sajadbot /usr/local/bin/sajadbot auth login را اجرا کنید؛ پس از ورود موفق، سرویس را دوباره راه بیندازید.

سرویس Ubuntu بالا نمی‌آید

خروجی sudo systemctl status sajadbot و sudo journalctl -u sajadbot -n 100 --no-pager را ببینید. کامل‌بودن سه مقدار تلگرام در /etc/sajadbot/sajadbot.env و انجام ورود اولیه را بررسی کنید.

خطای Database is locked می‌آید

احتمالاً نمونه‌ی دیگری از برنامه فعال است. همان پردازش را پیدا و متوقف کنید؛ تلاش تهاجمی راه‌حل مناسبی نیست.

فرآیند دیگری session را در اختیار دارد

فقط یک start یا groups refresh می‌تواند session را استفاده کند. نمونه‌ی قبلی را ببندید.
